The invariant layer is the fix, not the numbers. The critique's own conclusion was that the problem is architectural — several parts independently computing the same financial concepts. The engine now has one canonical cash-flow builder (build_payment_schedule), and every headline figure is re-derived from the schedule's own totals inside verify_returns + verify_scores. A failed reconciliation raises inside build_canonical_report and the API returns HTTP 500 — the report never renders. This immediately caught four real bugs the audit run below documents.

II. Real bugs the invariant layer caught

The audit exists precisely because the critique predicted these. Each was found on real data and fixed at its root.

  • schedulePayment plans not funding 100% of price (e.g. Savanna 10/80/11 = 101%) left sum(cash_flows) ≠ profit. A transparent balance entry now settles the schedule to the full purchase price.
  • roundingDivergent construction-year rounding — the total-return path applied 3 rental years while the schedule applied 4, breaking reconciliation by construction. Aggregates are now taken only from schedule totals.
  • statusUNKNOWN-status properties (6/6360) got construction timing in the leverage model but not in the total-return model — two different schedules, equity_gain ≠ total_profit. Both now share one construction rule.
  • scoringScore clamped from the unrounded mean while raw_score is stored rounded to 2dp — a 1-point divergence at .5 boundaries. The audit tolerates that artifact and still blocks real tampering.

III. What changed

Backend engine

  • returns/returns_engine.py — canonical build_payment_schedule; N/A over fallback for growth, construction, rental; stress tests None-safe; UNKNOWN-status construction rule unified.
  • report/audit_checks.py (new) — verify_returns + verify_scores, hard-fail raises.
  • report/canonical_report.py — audit wired into every report; growth/rental statuses; evidence recency fields.
  • evidence/evidence_engine.py — 24-month recency counting + confidence cap.
  • api/server.py — audit failure → HTTP 500; exit-strategy resolution.
  • risk/risk_engine.py — None-safe yield in opportunity scoring.

Frontend labels

  • ReturnsSection.tsx — “Total Return Est.” (netROI + 12-month trend) removed; engine IRR / Total ROI shown instead.
  • ReturnsSection.tsx — “ROE” cards relabeled Total ROI, with a separate Annualized Return (IRR) card.
  • ReturnsSection.tsx — cash-flow card uses engine total_return_pct stress values, not a nonexistent field.
  • pdf_report.py — None annual rent renders “N/A”, never 0.
